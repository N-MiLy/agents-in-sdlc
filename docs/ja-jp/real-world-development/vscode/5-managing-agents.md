GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat は作業をマシン上でリアルタイムに実行するため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加のプロンプトで会話を調整して、作業を改善または拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッション中にエージェントの方向を調整し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマは暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいという依頼がありました。新しい会話を一から始める代わりに、進行中のセッションの方向を調整して機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集ごとに差分がチャット内に表示され、**保持**/**元に戻す**を選択できます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインに表示されます。
   - **保持**を選択すると変更を承認します。
   - **元に戻す**を選択すると変更を元に戻し、エージェントにもう一度作業させます。
4. チャットの上部にある**変更されたファイル**を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止し、**許可**のプロンプトを表示します。許可する前にコマンドを確認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、実施した変更をまとめたメッセージが表示されます。

## エージェントの方向を調整してライト モードを追加する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けるため、エージェントは前の作業からコンテキストを引き継ぎます。変更したコンポーネント、スタイルの方法、ローカル ストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに行った変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラスト モードの場合と同じように、新しい編集を確認します。各差分で **保持**または**元に戻す**を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、切り替え UI を好ましくない方法でリファクタリングしようとした場合) は、チャット入力欄の横にある **停止**ボタンで中断し、説明を追加して続行します。

> [!TIP]
> 進行中のセッションの方向を調整すると、やり直すよりも速く作業できます。フォローアップ プロンプトで、調整 (「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」)、修正 (「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」)、範囲の拡張 (「2 つの切り替えにキーボード ショートカットも追加する」) を依頼できます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で**ソース管理**ビューを開きます。
2. 変更されたファイルの一覧をすべてレビューします。Astro コンポーネント、スタイル、関連テストの更新があるはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージによる設定の保持などが対象です。
4. 問題がなければ、ソース管理パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って進行中のセッションを監視し、各ファイルの編集を確認しながら、変更を承認または拒否し、コンテキストを失わずにフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を承認および拒否する
- フォローアップ プロンプトでセッションの方向を調整する
